# Ручная установка workflows для PR #11

Исправление Python уже опубликовано в ветке `arena/01a0a63a-vpnmy`, но ещё не в `main`.
Файлы в этой папке — шаблоны: GitHub Actions сам их не запускает.

## Проверить исправление до мёржа

1. На GitHub выберите ветку **`arena/01a0a63a-vpnmy`** (ветка PR #11).
2. Скопируйте полное содержимое `workflow-templates/ci.yml` в новый файл
   `.github/workflows/ci.yml` **в этой же ветке** и сохраните коммит прямо в неё.
3. Скопируйте полное содержимое `workflow-templates/update.yml` в
   `.github/workflows/update.yml` **в этой же ветке** и сохраните коммит.
4. В PR #11 откройте Checks и дождитесь зелёной проверки «Проверка кода».
   Коммит в открытый PR запускает `pull_request` workflow. Если GitHub запросит
   одобрение запуска, подтвердите его. CI использует код PR, а не старый код main.
5. В шаге «Установить и проверить Hysteria» должны быть `Version: 2.12.2`
   (между полями могут быть табуляции) и `resolve_hysteria: OK`.
   CI скачивает бинарник без кэша, проверяет закреплённый SHA-256 и resolver.
6. После успешной проверки смержите PR #11 в main либо сообщите агенту,
   что проверка завершилась, чтобы он продолжил мёрж и наблюдение.

## После мёржа

Изменение Python и production-workflow запустит «Обновление VPN-подписки» на main.
Проверьте успешную установку Hysteria, сборку и публикацию. В течение следующих
10–30 минут проверьте появление `HYSTERIA2` в `stats.json` → `protocols`:
узлам нужны две успешные проверки подряд (`stable_streak_required=2`), а наличие
доступных узлов не гарантировано. В коммите бота должен быть `data/source_health.json`.

CI только проверяет код и бинарник, не собирает и не публикует живую подписку.
Production-шаблон сохраняет расписание и публикацию только на main.
Версия app/v2.12.2 и SHA-256 не изменены. Не запускайте старый production-код
на main в ожидании исправления до мёржа.
