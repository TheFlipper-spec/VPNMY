# FL1P VPN

Автоматически обновляемая публичная VPN-подписка для русскоязычных пользователей.

- **Подписка:** https://theflipper-spec.github.io/VPNMY/FL1PVPN#FL1P%20VPN
- **Текстовый формат:** https://theflipper-spec.github.io/VPNMY/subscription.txt
- **Статус:** https://theflipper-spec.github.io/VPNMY/

## Что делает сервис

1. Каждые 10 минут GitHub Actions загружает конфигурации из включённых публичных источников.
2. Строгий парсер принимает VLESS, VMess, Trojan и **Hysteria2/hy2**, отбрасывает битые URI, повторяющиеся параметры, локальные адреса и дубликаты.
3. Вклад одного источника ограничен (`max_nodes_per_source`), поэтому гигантские списки не затаптывают пул тысячами непроверенных узлов: в проверку уходит небольшая, но репрезентативная выборка, стратифицированная по протоколам.
4. Кандидаты проходят DNS- и сетевую предпроверку: TCP-connect для классических протоколов и QUIC Version-Negotiation/ICMP-пробу для Hysteria2 (UDP). Дубликаты физических endpoint и клоны из одной /24-подсети не занимают несколько мест.
5. Для каждого узла короткого списка поднимается отдельный туннель: **Xray** для VLESS/VMess/Trojan и официальный клиент **Hysteria** для hysteria2 (оба скачиваются workflow с проверкой SHA-256).
6. Узел публикуется только после Cloudflare trace и дополнительного независимого HTTPS-запроса через этот туннель (плюс короткий замер скорости).
7. Новый узел попадает в подписку только после **двух успешных глубоких проверок подряд**; история отсекает «мёртвые» и хронически нестабильные конфигурации (при нехватке узлов действует безопасный откат к одной проверке).
8. Источник, который шесть запусков подряд недоступен или отдаёт ноль конфигураций, автоматически уходит в **карантин** и возвращается при первом же восстановлении; долго мёртвые источники удаляются командой `sources prune`.
9. Рабочие узлы оцениваются по стабильности, географии, задержке, скорости, защите (TLS/Reality/QUIC) и совместимости транспорта.
10. До 12 лучших конфигураций атомарно публикуются в Base64-файле `FL1PVPN` и raw-файле `subscription.txt`.

Принцип — **меньше, но идеально рабочие**: вместо тысяч полумёртых серверов в подписке всегда небольшой набор узлов, каждый из которых только что реально открыл интернет через туннель. Если все источники недоступны или работает меньше трёх узлов, последняя рабочая подписка **не затирается**. Страница статуса отдельно предупреждает, если опубликованные данные устарели.

## Для российской аудитории

Пул разделён на две категории:

- 7 мест — обычный интернет;
- 5 мест — конфигурации для сценариев белых списков.

В подписке приоритет получают иностранные и ближайшие европейские локации; российские узлы остаются резервом и ограничены максимум четырьмя из 12 мест. Поэтому при наличии рабочих кандидатов основную часть подписки составляют иностранные серверы. Широко поддерживаемые транспорты TCP, WebSocket и gRPC получают небольшой приоритет над экспериментальными. Задержка измеряется с GitHub runner и является контрольным показателем, а не обещанием пользовательского пинга.

Названия узлов формируются заново и одинаково отображаются в клиентах: флаг, `FL1P VPN`, страна, категория и HTTPS-задержка. Исходные рекламные названия не попадают в итоговый профиль. В начале `subscription.txt` и `FL1PVPN` стоят служебные строки `#profile-title`, `#profile-update-interval` и `#profile-web-page-url`, а у каждого URI имя дублируется в `#фрагменте` (для VMess ещё и в поле `ps`). Ссылку подписки можно импортировать как `.../FL1PVPN#FL1P VPN` — клиент подхватит название профиля из фрагмента URL.

## Источники

Источники живут в `config/subscription.json`: публичный HTTPS URL и категория `universal` или `whitelist`. Файл специально отформатирован так, чтобы источник можно было добавить или выключить руками. Ещё проще — через CLI:

```bash
python main.py sources
python main.py sources add https://example.com/sub.txt --name "Мой список" --category universal
python main.py sources rm example-com
python main.py sources off vedalink
python main.py sources on vedalink
```

`add` сам придумает короткий id из домена, отклонит HTTP, локальные адреса и повторяющийся URL. Выключить источник можно полем `"enabled": false` или командой `sources off`. Должен оставаться хотя бы один включённый источник.

Мёртвые источники обслуживаются автоматически: шесть неудачных запусков подряд (нет загрузки, ошибка парсинга или ноль валидных конфигураций) переводят источник в карантин (он виден на странице статуса, но узлы из него не берутся), а при восстановлении он сам возвращается в строй. Удалить источники, мёртвые долго (по умолчанию 36 запусков ≈ 6 часов), можно вручную:

```bash
python main.py sources prune            # показать кандидатов на удаление
python main.py sources prune --apply    # удалить из конфигурации
```

Сейчас используются:

- списки `igareck/vpn-configs-for-russia` для обычного интернета и белых списков (включая hysteria2);
- [VlessForU — working configs](https://sub.vlessfo.ru/vlessforu/working_configs.txt);
- [VEDA VPN](https://vedalink.xyz/sub/fJXfBACAy_fPp8Hr);
- [FastNodes — независимо проверенные узлы](https://github.com/rtwo2/FastNodes/blob/main/state/verified_last.txt) и их [протокольный список Hysteria2](https://github.com/rtwo2/FastNodes/blob/main/sub/protocols/hysteria2.txt) (обновляется ежечасно, мёртвые домены и закрытые порты отсеяны заранее);
- [0xRadikal/Free-v2ray-Configs — Hysteria2](https://github.com/0xRadikal/Free-v2ray-Configs/blob/main/protocols/hysteria2.txt).

Пустые и заблокированные списки (например, мёртвый `WHITE-CIDR-RU-checked.txt` и заблокированный GitHub по ToS `barry-far/V2ray-Configs`) в конфигурацию не добавляются, а гигантские агрегаторы с тысячами непроверенных узлов не используются вовсе — их поток отсеивается лимитом на источник и многоступенчатой проверкой.

Полные URI, UUID и пароли не попадают в `stats.json`, историю или логи. Публичный идентификатор подписки может находиться в пути URL источника — такой URL уже является открытой частью конфигурации репозитория.

## Структура

```text
.github/workflows/update.yml  # активное production-обновление
workflow-templates/update.yml # эталонный шаблон production workflow
workflow-templates/ci.yml     # шаблон линтера, тестов и проверки артефактов
config/subscription.json      # источники, квоты, лимиты и таймауты
vpnmy/sources.py              # CLI для источников (add/rm/on/off/prune)
vpnmy/source_health.py        # история источников и автокарантин
vpnmy/parser.py               # безопасный парсер VLESS/VMess/Trojan/Hysteria2
vpnmy/probe.py                # DNS/TCP- и UDP/QUIC-предпроверка
vpnmy/tunnel.py               # общая двойная HTTPS-проверка через SOCKS5
vpnmy/xray.py                 # конфиг и проверка через Xray
vpnmy/hysteria.py             # конфиг (YAML) и проверка через клиент Hysteria
vpnmy/verifier.py             # распределение узлов по ядрам Xray/Hysteria
vpnmy/selector.py             # лимиты, стратификация, scoring, квоты
vpnmy/publisher.py            # fail-safe публикация и stats.json
scripts/install_xray.py       # загрузка Xray с проверкой SHA-256
scripts/install_hysteria.py   # загрузка клиента Hysteria с проверкой SHA-256
index.html                    # адаптивная страница статуса
main.py                       # CLI-точка входа
```

В Git не складываются бинарники ядер, GeoIP-базы и runtime-логи. Workflow отдельно скачивает Xray `v26.3.27` и официальный клиент Hysteria `app/v2.12.2`; SHA-256 артефактов проверяется до запуска, а кэш GitHub Actions не даёт скачивать их повторно.

## GitHub Actions

Активный workflow обновления находится в `.github/workflows/update.yml`. Расписание `7,17,27,37,47,57 * * * *` запрашивает обновление каждые 10 минут; GitHub может запустить scheduled workflow с небольшой задержкой. Ручной production-запуск доступен через **Actions → Обновление VPN-подписки → Run workflow**.

GitHub App Arena не может пушить `.github/workflows/` без разрешения `workflows`. Эталонные файлы лежат в `workflow-templates/`. Чтобы включить CI и более точную проверку артефактов, скопируйте их через веб-интерфейс GitHub в `.github/workflows/update.yml` и `.github/workflows/ci.yml`.

## Локальный запуск

Требуются Python 3.11+ и установленный Xray Core:

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
export VPNMY_XRAY_BIN=/usr/local/bin/xray
export VPNMY_HYSTERIA_BIN=/usr/local/bin/hysteria   # необязательно: без него hy2-узлы пропускаются
python main.py
```

Проверка без записи:

```bash
python main.py --dry-run
```

Диагностический режим без Xray и Hysteria (только сетевая предпроверка):

```bash
python main.py --skip-deep-check --dry-run
```

`--skip-deep-check` не является production-проверкой: в `stats.json` будет `check_mode: "tcp_only"` и `status: "diagnostic"`.

## Ограничения

Это агрегатор бесплатных публичных конфигураций, а не собственная коммерческая VPN-инфраструктура. Узел может исчезнуть уже после успешной проверки. В таком случае обновите профиль и выберите другой узел. Используйте HTTPS, не передавайте особо чувствительные данные через неизвестные серверы и соблюдайте применимое законодательство. Условия лицензий исходных списков принадлежат их авторам.
