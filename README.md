# FL1P VPN

Автоматически обновляемая публичная VPN-подписка для русскоязычных пользователей.

- **Подписка:** https://theflipper-spec.github.io/VPNMY/FL1PVPN#FL1P%20VPN
- **Текстовый формат:** https://theflipper-spec.github.io/VPNMY/subscription.txt
- **Статус:** https://theflipper-spec.github.io/VPNMY/

## Что делает сервис

1. Каждые 30 минут (в 7 и 37 минут) GitHub Actions загружает конфигурации из включённых публичных источников.
2. Строгий парсер принимает VLESS, VMess, Trojan и **Hysteria2/hy2**, отбрасывает битые URI, повторяющиеся параметры, локальные адреса и дубликаты.
3. Вклад одного источника ограничен (`max_nodes_per_source`), поэтому гигантские списки не затаптывают пул тысячами непроверенных узлов: в проверку уходит небольшая, но репрезентативная выборка с бюджетом исследования ~70% лучшие известные / ~30% новые-или-давно-не-проверявшиеся, стратифицированная по протоколам и источникам (детерминированная ротация по часовому слоту защищает от голодания).
4. Кандидаты проходят **первый этап фильтрации** — DNS- и сетевую предпроверку с GitHub-раннера: TCP-connect для классических протоколов и QUIC Version-Negotiation/ICMP-пробу для Hysteria2 (UDP). Полностью мёртвые из США/ЕС IP отбрасываются, чтобы не тратить лимиты API второго этапа. Для доменных endpoint используется разрешённый IP, а не строковое имя; корректно обрабатываются IPv4 и IPv6. Дубликаты физических endpoint (`IP:port`) и клоны из одной подсети (`/24` IPv4, `/48` IPv6) не занимают несколько мест.
5. Выжившие проходят **второй этап фильтрации — проверку из российской сети через Globalping** (локация `RU`, токен из секрета `GLOBALPING_TOKEN`): TCP-проверка порта для классических протоколов и ICMP-пинг для Hysteria2 с 2–3 независимых российских узлов. Узел, который минимум два RU-проба подтвердили недоступным, исключается **до** глубокой проверки — так серверы, заблокированные в РФ (ТСПУ), но «живые» с точки зрения США/ЕС, не публикуются и не съедают бюджет ядер. Приоритет: опубликованные узлы → короткий список → остальные по локальному пингу; параллельность ограничена `asyncio.Semaphore` (12), на 429 — экспоненциальный backoff с учётом `Retry-After`. Бюджет за прогон (`ru_check_budget`, по умолчанию 125) дополнительно урезается фактической свободной квотой аккаунта (`GET /v1/limits`) — платные кредиты не расходуются, а при их списании прогон останавливается. Подробная сводка публикуется в `stats.json` (`ru_check`) и на страницу статуса.
6. Для каждого узла короткого списка поднимается отдельный туннель: **Xray** для VLESS/VMess/Trojan и официальный клиент **Hysteria** для hysteria2 (оба скачиваются workflow с проверкой SHA-256).
7. Узел публикуется только после **трёх независимых измерений** задержки через туннель (каждое — Cloudflare trace + второй независимый HTTPS-запрос `generate_204`/`success.txt` на свежем `Session`, без переиспользования соединения между попытками; внутри попытки trace и подтверждение могут переиспользовать соединение, но измеряется только trace). Считаются медиана, худшее и разброс (`max-min`); таймауты не отбрасываются, а входят в медиану как `timeout` (1500 мс порог). Скорость меряется один раз, чтобы не утраивать трафик.
8. Новый узел попадает в подписку только после **двух успешных глубоких проверок подряд**; история ведёт скользящее окно последних 10 циклов для оценки надёжности (миграция старой истории сохраняет полезные данные, не раздувая файл) и отсекает «мёртвые» и хронически нестабильные узлы (при нехватке узлов действует безопасный откат к одной проверке). Пропуск из-за лимита бюджета/отсутствия ядра не считается сетевым отказом.
9. Источник, который шесть запусков подряд недоступен или отдаёт ноль конфигураций, автоматически уходит в **карантин** и возвращается при первом же восстановлении; долго мёртвые источники удаляются командой `sources prune`.
10. Рабочие узлы оцениваются **без географии как показателя качества** (страна используется только для разнообразия): реальные проверки, надёжность в скользящем окне, задержка (медиана/худшее/разброс), стабильность (`streak`), скорость, защита (TLS/Reality/QUIC) и совместимость транспорта. `preferred_countries` остаётся читаемым для совместимости, но не влияет на скор и очередь проверок.
11. До 12 лучших конфигураций атомарно публикуются в Base64-файле `FL1PVPN` и raw-файле `subscription.txt` с лимитами разнообразия: максимум 3 узла одной страны (RU дополнительно до 4), 2 одного ASN, 1 на IP сервера, 2 на подсеть (`/24`/`/48`), 1 на выходной IP (разные входы могут вести на один выход — дедуплицируются). ASN определяется по IP сервера через `api.bgpview.io` (только IP, таймаут 3с, кэш, 5 потоков; ошибка не ломает сборку, неизвестный ASN не объединяется). Если подходящих узлов меньше `target_count`, публикуется меньшая подписка, но не ниже `min_publish_count` (3).

Принцип — **меньше, но идеально рабочие**: вместо тысяч полумёртых серверов в подписке всегда небольшой набор узлов, каждый из которых только что реально открыл интернет через туннель. Если все источники недоступны или работает меньше трёх узлов, последняя рабочая подписка **не затирается**. Страница статуса отдельно предупреждает, если опубликованные данные устарели.

## Для российской аудитории

Пул разделён на две категории (названия не меняются):

- 7 мест — обычный интернет;
- 5 мест — конфигурации для сценариев белых списков.

Разнообразие важнее концентрации: по умолчанию не более 3 узлов одной страны (RU дополнительно до 4), 2 одного ASN, 1 на IP, 2 на подсеть, 1 на выходной IP. Поэтому даже при наличии 6 финских узлов в одной сети (`/24`, один ASN) в подписку попадёт максимум 2, а остальные места займут DE/LT/EE/PL/RU в разных сетях. Страна **не** даёт бонус к качеству — только ограничивает разнообразие. Широко поддерживаемые транспорты TCP, WebSocket и gRPC получают небольшой приоритет над экспериментальными. Задержка — медиана трёх измерений через туннель с GitHub runner (порог 1500 мс, штраф за разброс); стабильный `650/700/680` выигрывает у нестабильного `400/450/3800` при прочих равных. Это контрольный показатель, а не обещание пинга из Казани/мобильной сети — без измерения из российской сети доступность не гарантируется (см. план отдельной точки проверки).

## Российская проверка (Globalping, локация RU)

Отдельный этап между сетевой предпроверкой и глубокой проверкой отвечает на вопрос «достигает ли пользователь из РФ этот сервер»:

- **Что замеряется.** Для VLESS/VMess/Trojan — TCP-подключение к порту узла; для Hysteria2 — ICMP-пинг (UDP-портов в Globalping нет). Измерение идёт с 2–3 независимых российских узлов (`locations: [{"country": "RU"}]`, `limit`), считается медиана RTT.
- **Вердикты.** «Доступно» — хоть один RU-проб ответил. «Заблокировано в РФ» — минимум два независимых RU-проба не подключились (такой узел исключается из проверки и подписки, в истории узла растёт `ru_blocked_streak`). Всё неоднозначное — «неизвестно»: узел не штрафуется, молчание ICMP для Hysteria2 тоже считается «неизвестно», а не блокировкой (фаерволы часто гасят ping).
- **Что это ловит, а что нет.** Ловит IP-блокировки (включая блокировки сервера в РФ), мёртвые порты и крупные сетевые проблемы. **Не ловит** SNI-DPI (чистый TCP-connect не несёт SNI), не измеряет скорость/качество туннеля и не эквивалентен домашней/мобильной сети конкретного города — пробы Globalping в РФ это дата-центры и энтузиасты (Moscow/St. Petersburg/Krasnodar и др.). Известный компромисс: сервер, который намеренно блокирует дата-центровые IP (частая практика анти-абуза), может быть помечен «заблокированным в РФ», хотя резидентные пользователи до него доходят; узлы пере-проверяются каждые 30 минут, а в `stats.json` видно причину (`blocked` по ≥2 пробам). Глубокая проверка через туннель остаётся финальным словом о качестве.
- **Лимиты и отказоустойчивость.** Токен — GitHub Secret `GLOBALPING_TOKEN` (генерируется на https://dash.globalping.io/tokens). Бесплатная квота аккаунта (~250 измерений/час) контролируется через `GET /v1/limits`: бюджет прогона урезается до свободной квоты минус резерв, поэтому два запуска в час укладываются в лимит (по умолчанию `ru_check_budget: 125`). 429/5xx/сетевые сбои — экспоненциальный backoff с джиттером (до 30 с), 422 «нет RU-пробов» — узел помечается «неизвестно», а не «блокировка». Общий дедлайн этапа (`ru_check_deadline_seconds`, 420 с) гарантирует, что сбой Globalping не проткнёт 12-минутное окно workflow: непроверенные узлы просто идут дальше по обычной логике. Если этап отключён (нет токена) — сборка работает в прежнем режиме, а `stats.json` честно показывает `ru_check.enabled: false` с причиной.

Названия узлов формируются заново и одинаково отображаются в клиентах: флаг, `FL1P VPN`, страна, категория и HTTPS-задержка. Исходные рекламные названия не попадают в итоговый профиль. В начале `subscription.txt` и `FL1PVPN` стоят служебные строки `#profile-title`, `#profile-update-interval` и `#profile-web-page-url`, а у каждого URI имя дублируется в `#фрагменте` (для VMess ещё и в поле `ps`). Ссылку подписки можно импортировать как `.../FL1PVPN#FL1P VPN` — клиент подхватит название профиля из фрагмента URL.

## Источники

Источники живут в `config/subscription.json`: публичный HTTPS URL и категория `universal` или `whitelist`. Файл специально отформатирован так, чтобы источник можно было добавить или выключить руками. Ещё проще — через CLI:

```bash
python main.py sources
python main.py sources add https://example.com/sub.txt --name "Мой список" --category universal
python main.py sources rm example-com
python main.py sources off vedalink
python main.py sources on vedalink
```

`add` сам придумает короткий id из домена, отклонит HTTP, локальные адреса и повторяющийся URL. Выключить источник можно полем `"enabled": false` или командой `sources off`. Должен оставаться хотя бы один включённый источник.

Мёртвые источники обслуживаются автоматически: шесть неудачных запусков подряд (нет загрузки, ошибка парсинга или ноль валидных конфигураций) переводят источник в карантин (он виден на странице статуса, но узлы из него не берутся), а при восстановлении он сам возвращается в строй. Удалить источники, мёртвые долго (по умолчанию 36 запусков ≈ 6 часов), можно вручную:

```bash
python main.py sources prune            # показать кандидатов на удаление
python main.py sources prune --apply    # удалить из конфигурации
```

Сейчас используются:

- списки `igareck/vpn-configs-for-russia` для обычного интернета и белых списков (включая hysteria2);
- [VlessForU — working configs](https://sub.vlessfo.ru/vlessforu/working_configs.txt);
- [VEDA VPN](https://vedalink.xyz/sub/fJXfBACAy_fPp8Hr);
- [FastNodes — независимо проверенные узлы](https://github.com/rtwo2/FastNodes/blob/main/state/verified_last.txt) и их [протокольный список Hysteria2](https://github.com/rtwo2/FastNodes/blob/main/sub/protocols/hysteria2.txt) (обновляется ежечасно, мёртвые домены и закрытые порты отсеяны заранее);
- [0xRadikal/Free-v2ray-Configs — Hysteria2](https://github.com/0xRadikal/Free-v2ray-Configs/blob/main/protocols/hysteria2.txt).

Пустые и заблокированные списки (например, мёртвый `WHITE-CIDR-RU-checked.txt` и заблокированный GitHub по ToS `barry-far/V2ray-Configs`) в конфигурацию не добавляются, а гигантские агрегаторы с тысячами непроверенных узлов не используются вовсе — их поток отсеивается лимитом на источник и многоступенчатой проверкой.

Полные URI, UUID и пароли не попадают в `stats.json`, историю или логи. Публичный идентификатор подписки может находиться в пути URL источника — такой URL уже является открытой частью конфигурации репозитория.

## Структура

```text
.github/workflows/update.yml  # активное production-обновление
workflow-templates/update.yml # эталонный шаблон production workflow
workflow-templates/ci.yml     # шаблон линтера, тестов и проверки артефактов
config/subscription.json      # источники, квоты, лимиты и таймауты
vpnmy/sources.py              # CLI для источников (add/rm/on/off/prune)
vpnmy/source_health.py        # история источников и автокарантин
vpnmy/parser.py               # безопасный парсер VLESS/VMess/Trojan/Hysteria2
vpnmy/probe.py                # DNS/TCP- и UDP/QUIC-предпроверка (1-й этап)
vpnmy/globalping.py           # проверка из российской сети через Globalping (2-й этап)
vpnmy/tunnel.py               # общая двойная HTTPS-проверка через SOCKS5
vpnmy/xray.py                 # конфиг и проверка через Xray
vpnmy/hysteria.py             # конфиг (YAML) и проверка через клиент Hysteria
vpnmy/verifier.py             # распределение узлов по ядрам Xray/Hysteria
vpnmy/selector.py             # лимиты, стратификация, scoring, квоты
vpnmy/publisher.py            # fail-safe публикация и stats.json
scripts/install_xray.py       # загрузка Xray с проверкой SHA-256
scripts/install_hysteria.py   # загрузка клиента Hysteria с проверкой SHA-256
index.html                    # адаптивная страница статуса
main.py                       # CLI-точка входа
```

В Git не складываются бинарники ядер, GeoIP-базы и runtime-логи. Workflow отдельно скачивает Xray `v26.3.27` и официальный клиент Hysteria `app/v2.12.2`; SHA-256 артефактов проверяется до запуска, а кэш GitHub Actions не даёт скачивать их повторно.

## GitHub Actions

Активный workflow обновления находится в `.github/workflows/update.yml`. Расписание `7,37 * * * *` запрашивает обновление каждые 30 минут (в 7 и 37 минут); GitHub может запустить scheduled workflow с небольшой задержкой. Ручной production-запуск доступен через **Actions → Обновление VPN-подписки → Run workflow**.

Для российской проверки нужен секрет **`GLOBALPING_TOKEN`** (Settings → Secrets and variables → Actions): токен создаётся на <https://dash.globalping.io/tokens> и передаётся workflow переменной `GLOBALPING_TOKEN`. Без секрета этап российской проверки корректно пропускается, и публикация не ломается.

GitHub App Arena не может пушить `.github/workflows/` без разрешения `workflows`. Эталонные файлы лежат в `workflow-templates/`. Чтобы включить CI и более точную проверку артефактов, скопируйте их через веб-интерфейс GitHub в `.github/workflows/update.yml` и `.github/workflows/ci.yml`.

## Локальный запуск

Требуются Python 3.11+ и установленный Xray Core:

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
export VPNMY_XRAY_BIN=/usr/local/bin/xray
export VPNMY_HYSTERIA_BIN=/usr/local/bin/hysteria   # необязательно: без него hy2-узлы пропускаются
python main.py
```

Проверка без записи:

```bash
python main.py --dry-run
```

Диагностический режим без Xray и Hysteria (только сетевая предпроверка):

```bash
python main.py --skip-deep-check --dry-run
```

`--skip-deep-check` не является production-проверкой: в `stats.json` будет `check_mode: "tcp_only"` и `status: "diagnostic"`.

## Ограничения

Это агрегатор бесплатных публичных конфигураций, а не собственная коммерческая VPN-инфраструктура. Узел может исчезнуть уже после успешной проверки. В таком случае обновите профиль и выберите другой узел. Используйте HTTPS, не передавайте особо чувствительные данные через неизвестные серверы и соблюдайте применимое законодательство. Условия лицензий исходных списков принадлежат их авторам.
