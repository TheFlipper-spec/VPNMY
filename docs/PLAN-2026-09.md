## Что меняем

1. **Hysteria2**: парсер `hysteria2://` и `hy2://` (auth опционален, sni, insecure,
   pinSHA256, obfs=salamander, alpn, mport/port-hopping); официальный клиент Hysteria
   v2.12.2, скачивается и пинится SHA-256; та же двойная HTTPS-проверка через SOCKS5,
   что и у Xray; UDP/QUIC-предпроверка (Version-Negotiation probe + ICMP).
2. **Меньше, но идеально рабочие**:
   - лимит конфигов от одного источника (`max_nodes_per_source`);
   - стратифицированная по протоколам выборка кандидатов;
   - ограничение на число узлов из одной /24-подсети (анти-клон);
   - публикация новых узлов только после **2 успешных глубоких проверок подряд**
     (с откатом к одной, если рабочих узлов критически мало).
3. **Автокарантин источников**: источник, который N запусков подряд недоступен или
   отдаёт ноль конфигов, уходит в карантин (узлы не берутся, статистика видна на
   странице), автоматически возвращается при восстановлении; CLI `sources prune`
   удаляет долго мёртвые источники из конфига.
4. **Умный shortlist**: гарантированное место hysteria2 в проверке, /24-разнообразие
   уже на стадии Xray/Hysteria-проверки, бонус QUIC/Reality в скоринге.
5. Workflow ставит и пинит оба ядра (Xray + Hysteria), артефакт-проверка знает hy2.

## Реализация

- `vpnmy/parser.py` — разбор `hysteria2://`/`hy2://`: опциональный auth, sni, insecure,
  pinSHA256, alpn, obfs=salamander с обязательным паролем, port hopping (`mport`),
  нормализация опций; мусорные/локальные ссылки отбрасываются.
- `vpnmy/probe.py` — TCP-предпроверка классики и UDP/QUIC-предпроверка Hysteria2
  (корректный QUIC Initial с неподдерживаемой версией → ответ Version Negotiation;
  ICMP port unreachable → мёртв; молчание файрвола → консервативный fallback).
- `vpnmy/tunnel.py` — общий для ядер SOCKS5-прогон: Cloudflare trace, независимый
  HTTPS-запрос (gstatic 204 / firefox success.txt), короткий speed-test.
- `vpnmy/hysteria.py` — официальный клиент apernet/hysteria `app/v2.12.2`:
  YAML/JSON-конфиг (`lazy: true`, socks5, tls, pinSHA256, salamander, hopping),
  бинарь опционален (`VPNMY_HYSTERIA_BIN`), при отсутствии hy2-узлы пропускаются,
  но не считаются отказами.
- `vpnmy/verifier.py` — единый пул глубокой проверки с распределением по ядрам.
- `vpnmy/source_health.py` + `data/source_health.json` — стрики, автокарантин,
  авто-восстановление; CLI `python main.py sources prune [--apply]`.
- `vpnmy/selector.py` — лимит на источник, стратификация выборки по протоколам,
  гарантия доли Hysteria2 в shortlist, /24-лимит клонов, протокольный бонус,
  требование серии успехов для новых узлов.
- `scripts/install_hysteria.py`, оба workflow — пиннинг и кэш второго ядра.

## Остаточные ограничения (честно)

- UDP-предпроверка для obfs/агрессивных файрволов консервативна (молчание трактуется
  как «вероятно жив»), финальное решение всегда за живым Hysteria-клиентом.
- Требование двух успешных проверок задерживает появление новых узлов на ~10–20 минут;
  при дефиците узлов действует откат к одиночному подтверждению, подписка не пустеет.
- Port hopping проверяется на первом порту диапазона; полный перебор делает клиент.
- Песочница не выпускает наружу (кроме github API), поэтому «боевые» туннели
  проверяются в GitHub Actions — для этого обновлён workflow и закреплён SHA клиента.
